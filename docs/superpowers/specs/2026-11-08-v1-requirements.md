# VOXEL SANDBOX — VERSION 1.0

## Разработка первой играбельной версии на Rust + Bevy

### 1. Твоя роль

Ты — ведущий Rust-разработчик, архитектор игровых движков и специалист по оптимизации воксельных миров.

Твоя задача — **реализовать полностью играбельную первую версию Voxel Sandbox v1.0**, используя существующий GitHub-репозиторий:

[https://github.com/tuulaleksandr5-byte/voxel-sandbox-rust](https://github.com/tuulaleksandr5-byte/voxel-sandbox-rust)

Это реальный проект, который будет постепенно расширяться до большой 3D-песочницы с автоматизацией, мобами, боссами, транспортом, драконами и мультиплеером.

**Сейчас реализуй только фундамент игры, но сделай его качественно.**

Не создавай отдельный демонстрационный проект вместо существующего репозитория.

### 2. Технологии

Используй:

- Язык: Rust, Edition 2024.
- Движок: Bevy 0.20.1.
- Графика: Bevy Renderer / wgpu.
- Шейдеры: WGSL при необходимости.
- Генерация: детерминированная по seed.
- Меши: greedy meshing.
- Хранение мира: компактные чанки.
- Сохранения: serde и версионированный формат.
- Основная платформа: Windows x64.
- Дополнительная платформа: Linux x64.

Перед реализацией проверь актуальную совместимость всех библиотек.

Зафиксируй версии зависимостей и Rust toolchain. Не используй неподтверждённые API.

**Запрещено заменять Rust + Bevy на JavaScript, HTML, Unity, Godot или другой движок.**

### 3. Что должно быть в версии 1.0

#### 3.1. Главное меню

При запуске игры открывается главное меню.

Кнопки:

- Играть.
- Создать мир.
- Загрузить мир.
- Настройки.
- Выход.

При создании мира пользователь выбирает:

- Название мира.
- Seed — произвольное число или автоматически сгенерированное значение.
- Режим: творческий.

Мир сохраняется на компьютере пользователя.

#### 3.2. Воксельный мир

Параметры:

```text
WORLD_MIN_Y = -64
WORLD_MAX_Y = 320
SEA_LEVEL = 63

CHUNK_WIDTH = 16
CHUNK_DEPTH = 16
SECTION_HEIGHT = 16
```

Использовать вертикальные секции 16×16×16.

Обязательные требования:

1. Практически неограниченный горизонтальный мир в пределах координатного типа.
2. Генерация чанков вокруг игрока.
3. Автоматическая выгрузка удалённых чанков.
4. Фоновая генерация.
5. Отсечение невидимых граней.
6. Greedy meshing.
7. Корректные отрицательные координаты.
8. Отсутствие заметных блокировок основного потока при загрузке.
9. Детерминированная генерация: одинаковые seed и версия генератора дают одинаковый результат.

При изменении блока обновляй только затронутые секции и необходимые границы соседних секций.

#### 3.3. Генерация ландшафта

Используй noise-based алгоритмы.

Для первой версии достаточно следующих биомов:

| Биом    | Особенности               |
| ------- | ------------------------- |
| Равнина | Трава, небольшие холмы    |
| Лес     | Деревья, трава            |
| Пустыня | Песок, дюны               |
| Горы    | Высокий каменистый рельеф |
| Океан   | Вода и морское дно        |

Обязательные структуры:

- Деревья.
- Простые пещеры.
- Поверхностные водоёмы.

Биомы должны переходить друг в друга без резких искусственных границ.

#### 3.4. Блоки

Реализуй реестр блоков со стабильными идентификаторами.

Минимальный набор:

1. Воздух.
2. Трава.
3. Земля.
4. Камень.
5. Глубинный камень.
6. Песок.
7. Гравий.
8. Дерево.
9. Листва.
10. Доски.
11. Булыжник.
12. Стекло.
13. Вода.
14. Коренная порода.
15. Снег.
16. Песчаник.

Для каждого блока предусмотрены свойства:

```text
id
name
texture
hardness
collision
opacity
light_emission
```

Некоторые свойства пока могут использовать стандартные значения, но структура должна позволять расширение.

Блоки должны иметь визуально различимые поверхности. Используй собственные текстуры или процедурные материалы, не копируя защищённые ресурсы Minecraft.

#### 3.5. Игрок

Реализуй камеру от первого лица.

Управление:

| Клавиша | Действие        |
| ------- | --------------- |
| W A S D | Передвижение    |
| Мышь    | Обзор           |
| Space   | Прыжок          |
| Shift   | Бег             |
| Ctrl    | Приседание      |
| E       | Инвентарь       |
| 1–9     | Выбор слота     |
| ЛКМ     | Разрушить блок  |
| ПКМ     | Установить блок |
| Esc     | Пауза           |

Обязательные механики:

- Гравитация.
- Столкновения со всеми твёрдыми блоками.
- Перемещение по неровной поверхности.
- Запрет прохода через стены.
- Запрет размещения блока внутри игрока.
- Корректная точка появления.
- Ограничение взаимодействия с блоками по расстоянию.

Используй 3D DDA ray casting для определения выбранного блока.

#### 3.6. Строительство

Игрок должен иметь возможность:

- Выбрать блок.
- Установить его.
- Разрушить существующий.
- Строить стены и здания.
- Копать вниз.
- Строить в высоту.
- Изменять рельеф.
- Взаимодействовать с блоками на границах чанков.

Все изменения должны правильно отображаться и сохраняться.

#### 3.7. Инвентарь

Реализуй простой творческий инвентарь:

- Хотбар на 9 слотов.
- Каталог всех доступных блоков.
- Выбор блока.
- Перемещение блоков в хотбар.
- Подсветка выбранного слота.
- Отображение выбранного блока.

В версии 1.0 количество блоков не ограничено.

Полноценный инвентарь выживания, крафт и прочность инструментов пока не требуются.

#### 3.8. Сохранение и загрузка

Реализуй:

- Создание нового мира.
- Список существующих миров.
- Сохранение изменений блоков.
- Сохранение положения игрока.
- Сохранение seed.
- Сохранение игрового времени.
- Загрузку мира после закрытия игры.
- Автосохранение.
- Ручное сохранение.
- Проверку целостности данных.

Сохранения должны иметь версию формата. Используй безопасную запись через временный файл с атомарной заменой там, где это поддерживается, и восстановление после сбоя.

При повторном запуске пользователь должен увидеть свои постройки.

#### 3.9. Графика

Для версии 1.0:

- Собственные пиксельные текстуры.
- Освещение от солнца.
- Небо.
- Простая смена дня и ночи.
- Туман на дальнем расстоянии.
- Вода с простой прозрачностью.
- Перекрестие в центре экрана.
- Подсветка выбранного блока.
- Настраиваемая дальность прорисовки.

Не добавляй тяжёлые графические эффекты, если они ухудшают производительность.

#### 3.10. Настройки

Минимальное меню настроек:

- Разрешение окна.
- Полноэкранный режим.
- Дальность прорисовки: 4–16 чанков.
- Чувствительность мыши.
- Вертикальная синхронизация.
- Общая громкость.

Настройки должны сохраняться между запусками.

### 4. Архитектура

Не создавай сразу десятки пустых crates.

Предпочтительная начальная структура:

```text
voxel-sandbox-rust/
├── Cargo.toml
├── Cargo.lock
├── rust-toolchain.toml
├── README.md
├── crates/
│   ├── game_core/
│   ├── game_world/
│   ├── game_render/
│   ├── game_simulation/
│   └── game_ui/
├── apps/
│   └── client/
├── assets/
│   ├── textures/
│   └── data/
├── tests/
└── docs/
```

Адаптируй структуру к существующему репозиторию и сохраняй работающий код.

Отдели игровую симуляцию от рендера. Не создавай отдельную ECS-сущность для каждого обычного блока.

Генератор, хранилище мира и логика взаимодействий должны тестироваться без открытия графического окна.

Архитектура должна позволять добавить в будущем:

- Мультиплеер с авторитетным сервером.
- Руды и инструменты.
- Крафт.
- Мобов.
- Боссов.
- Механические сети.
- Самолёты.
- Драконов.
- Другие измерения.

Не реализуй эти механики сейчас.

### 5. Производительность

Целевой тестовый компьютер:

```text
CPU: 6 ядер
RAM: 16 GB
GPU: GTX 1660 или аналог
Resolution: 1920x1080
Target: 60 FPS
```

Оптимизации:

- Greedy meshing.
- Face culling.
- Frustum culling.
- Chunk streaming.
- Фоновая генерация.
- Ограничение количества создаваемых мешей за кадр.
- Минимизация лишних аллокаций.
- Использование ECS без избыточного числа сущностей.

60 FPS — целевой показатель, а не гарантия до проведения реального тестирования.

### 6. Порядок разработки

Работай небольшими завершёнными задачами.

**Шаг 1 — Ядро приложения**

Создай запускаемое Bevy-приложение с камерой, управлением и тестовой сценой.

**Шаг 2 — Блочный мир**

Реализуй реестр блоков, координаты, секции и хранение чанков.

**Шаг 3 — Рендер**

Добавь построение мешей, отсечение невидимых граней и greedy meshing.

**Шаг 4 — Генерация**

Создай процедурный мир с биомами и деревьями.

**Шаг 5 — Игрок**

Добавь управление, коллизии, гравитацию и прыжки.

**Шаг 6 — Строительство**

Реализуй разрушение и размещение блоков.

**Шаг 7 — Интерфейс**

Добавь меню, хотбар, инвентарь и настройки.

**Шаг 8 — Сохранения**

Реализуй создание, загрузку, сохранение миров.

**Шаг 9 — Оптимизация и тесты**

Проверь производительность, устранение ошибок и сохранность данных.

Задачи, не имеющие общих изменяемых файлов и зависимостей, можно выполнять параллельно в отдельных ветках.

### 8. Что запрещено

1. Не заменять игру текстовой демонстрацией.
2. Не заменять Rust на другой язык.
3. Не имитировать работающие механики.
4. Не использовать один объект Cube для каждого блока вместо системы мешей.
5. Не создавать всю карту заранее.
6. Не блокировать основной поток длительной генерацией.
7. Не удалять существующий рабочий код без необходимости.
8. Не копировать защищённые модели и текстуры других игр.
9. Не добавлять сложные механики, не относящиеся к версии 1.0.
10. Не утверждать, что сборка работает, без реальной проверки.

### 10. Итоговый результат

Я хочу получить **настоящую запускаемую игру Voxel Sandbox v1.0**.

Минимальный игровой сценарий:

1. Запускаю игру.
2. Нажимаю «Создать мир».
3. Ввожу название и seed.
4. Появляюсь в процедурно созданном мире.
5. Хожу, прыгаю и исследую местность.
6. Ломаю и устанавливаю блоки.
7. Строю собственный дом.
8. Сохраняю мир.
9. Закрываю игру.
10. Запускаю игру снова и продолжаю строительство.

Все десять действий должны реально работать.

**Начинай с проверки существующего репозитория, затем переходи к реализации. Не останавливайся на одном лишь плане, если доступна среда разработки. Если задача слишком большая для одного запуска, заверши максимально возможный работающий этап и точно укажи оставшиеся задачи.**

Финальный результат должен включать исходный код, инструкции по запуску, тесты и Windows-сборку при технической возможности.
