# Параллельная работа разработчиков / ИИ

## Зоны ответственности

| Направление | Папка | Можно независимо после |
|---|---|---|
| Core | `crates/game_core` | Согласование публичных контрактов |
| World | `crates/game_world` | Типы координат и блоков |
| Render | `crates/game_render` | Интерфейс доступа к секциям |
| Player | `crates/game_player` (позже) | Интерфейс мира и игровых команд |
| Items | `crates/game_items` (позже) | Типы идентификаторов предметов |
| Persistence | `crates/game_persistence` | Формат и версия сохраняемого состояния |
| UI | `crates/game_ui` (позже) | Модель действий и состояние игрока |
| QA | `.github/workflows`, `tests` | Тестовые сценарии и интерфейсы |

## Зафиксированные границы

См. [контракты ядра](CORE_CONTRACTS.md): координаты и Section для World/Render,
WorldRead и CommandSink для Player, ItemId и InventoryRead/Write для Items,
WorldMetadata и SectionStore для Persistence. Эти задачи можно реализовывать
в отдельных crates без изменения core. Поля существующих команд/событий,
семантику ID и координат менять только после согласования со смежными задачами.
Механические сети #22 не входят в ядро версии 1.0.

## Git-процесс

1. От `main` создаётся ветка `feature/<module>-<short-task>`.
2. Разработчик меняет только назначенную подсистему и её тесты.
3. Изменения публичных контрактов `game_core` требуют предварительного согласования.
4. Тесты + ревью → Pull Request → интеграция.
5. Один интегратор следит, чтобы ветки не меняли один и тот же файл без договорённости.

## Общие правила для ИИ

- Не выдавай псевдокод за рабочий код.
- Не объявляй тесты успешными без выполнения команд.
- Не меняй размеры чанков и диапазон мира без архитектурного решения.
- Не копируй ассеты или код Minecraft/Terraria/модов.
- Сначала маленькое работающее изменение, потом следующий функциональный блок.
